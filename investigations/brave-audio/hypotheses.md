Declared shared settings are candidates for comparison, not evidence that an extension or flag caused the fault; laptop runtime versions and the precise symptom match remain unverified.

## Scope question, not a competing root cause

**Q1: Is persistent bad state specific to one Brave instance/Pulse connection, or does a fresh independent client immediately inherit it?** U06 cannot answer until “new profile” is defined. Profiles within the same user-data directory do not constitute verified process isolation. Inspect actual browser/audio-service PIDs and Pulse client identities.

If an independent client works while the original fails, H1b still remains possible: server state can be per client. It also leaves profile settings/extensions as a confound when the independent instance uses a clean user-data directory. If both fail, that does not prove hardware failure: shared server/device state and deterministic browser behavior remain possible. See P01.

## Trigger question

Meet/ChatGPT preceding failure (U03) does not show what they change. Candidate dimensions include stream creation/destruction, concurrency, processing requests, and capture/playback combinations. Wispr reliability is a useful control, not evidence that it omits WebRTC or uses a known different audio API. Exact app requests must be measured before attributing cause.
