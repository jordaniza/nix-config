# Working on this configuration

- Before diagnosing desktop integration, browser, audio, clipboard, screen-sharing or GPU issues, read [README.md — Known desktop issues and fixes](README.md#known-desktop-issues-and-fixes). It records verified fixes, working graphics settings and unresolved symptoms.
- Start relevant desktop diagnostics with a read-only inventory of user and system service masks (`systemctl --user list-unit-files --state=masked,masked-runtime` and `systemctl list-unit-files --state=masked,masked-runtime`). Masks are overrides that can persist across reboot, not necessarily failed or running services. Inspect relevant unit definitions and logs; do not unmask services automatically or assume every mask is wrong.
- A running portal is not proof that all interfaces work. Check the required D-Bus interface and reproduce the actual operation. The README documents the previously masked GTK backend and Slack handoff repair.
- Preserve the verified Brave XWayland/GTK 3 baseline in `config/brave/default.nix`. GPU selection is automatic in the shared config; desktop-only RX580 forcing was tested separately. Do not restore native Wayland, globally force a GPU, disable acceleration, or change graphics versions during unrelated diagnostics without an explicit test plan and user agreement.
- Treat currently working audio/clipboard behavior as an observation, not a confirmed fix. Capture a recurrence before restarting apps or changing settings where practical; use synthetic test data and never collect clipboard contents, authentication callback tokens or private recordings by default.
- Keep diagnosis separate from implementation. Preserve existing user edits, the intentional machine-ID/`--impure` workflow and necessary package pins. Document evidence and limitations; make one controlled change at a time.
