# Working on this configuration

- **User-managed builds and activation:** The user runs Nix builds, rebuilds, upgrades and activation. Do not run these unless explicitly delegated for that turn. Read-only evaluation and static checks are allowed. After approved edits, state what was verified and tell the user when to rebuild/apply the configuration. Do not update dependency pins unless separately requested and approved.

- **Reports exception:** The user authorizes creating and updating reports under `reports/` and adding relevant entries to `.gitignore` without a separate write preview or approval. Keep reports free of secrets and private payloads; ignored files are not a security boundary. This exception does not authorize implementation changes, builds, activation, service changes or dependency updates. All other configuration changes still require the preview and approval below.

- **Markdown exception:** The user authorizes additions and edits to Markdown files without a separate write preview or approval. This overrides the preview requirement below for Markdown additions and edits; it does not authorize builds, activation, service changes or non-Markdown configuration edits.

- **Preview before writing:** Before making any changes to this Nix configuration repository or its related managed configuration, show the complete proposed diff, including new files and deletions, explain the expected behavior and risks, and wait for explicit user approval before writing. A request to implement a feature is not approval of an unseen diff. If the proposed changes expand or differ from the approved preview, preview the revised changes and obtain approval again. Read-only inspection is allowed without a write preview. Builds, activation, service changes and other runtime actions must also stay within the user's approved scope; approval to edit does not automatically authorize activation.
- Before diagnosing desktop integration, browser, audio, clipboard, screen-sharing or GPU issues, read [README.md — Known desktop issues and fixes](README.md#known-desktop-issues-and-fixes). It records verified fixes, working graphics settings and unresolved symptoms.
- Before investigating recurring Brave/Meet/ChatGPT microphone degradation, read [the canonical audio investigation](investigations/brave-audio/README.md) and its completed-test ledger. Keep hypotheses, evidence, online sources and decisions current there. Name the new discriminating question before another experiment; do not repeat the broad app/profile/native-recording/USB matrix without new evidence. Preserve the measured September 10 per-stream timing/drop finding and distinguish it from separate microphone-disconnection incidents.
- Start relevant desktop diagnostics with a read-only inventory of user and system service masks (`systemctl --user list-unit-files --state=masked,masked-runtime` and `systemctl list-unit-files --state=masked,masked-runtime`). Masks are overrides that can persist across reboot, not necessarily failed or running services. Inspect relevant unit definitions and logs; do not unmask services automatically or assume every mask is wrong.
- A running portal is not proof that all interfaces work. Check the required D-Bus interface and reproduce the actual operation. The README documents the previously masked GTK backend and Slack handoff repair.
- Preserve the Brave XWayland/GTK 3 flags in `config/brave/default.nix`. Desktop GPU selection comes from `hardware/desktop.nix`; laptop selection remains automatic. Preserve the restored Brave 1.93.138 pin: downgrading to 1.82.172 crashed the existing profile while a temporary profile worked. The restored package and wrapper need fresh runtime validation. Do not restore native Wayland, globally force a GPU, disable acceleration, or change graphics versions during unrelated diagnostics without an explicit test plan and user agreement.
- Treat currently working audio/clipboard behavior as an observation, not a confirmed fix. Capture a recurrence before restarting apps or changing settings where practical; use synthetic test data and never collect clipboard contents, authentication callback tokens or private recordings by default.
- Keep diagnosis separate from implementation. Preserve existing user edits, the intentional machine-ID/`--impure` workflow and necessary package pins. Document evidence and limitations; make one controlled change at a time.
